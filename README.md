# Хроники Падших — глобальная статистика смертей Path of Exile 2

Неофициальный трекер смертей персонажей в PoE2: причины, локации, классы, уровни,
реестр отчётов игроков, личный кабинет и Spotify-плеер с переключением треков.

Дизайн собран «под игру»: обсидиановый фон, латунные рамки, гравюрные шрифты
(Cinzel / Cormorant Garamond), кроваво-красные акценты, зерно и виньетка.

**Сайт в сети:** <https://yogi13en.github.io/poe2-track/> · репозиторий:
<https://github.com/yogi13en/poe2-track>

---

## Что внутри

| Раздел | Описание |
|---|---|
| **Сводка** | всего смертей, за 24 часа, смертей в минуту, средний уровень, доля Hardcore, самая смертоносная локация, главная причина, класс-«самоубийца», рекорд уровня |
| **Аналитика** | топ-8 локаций, доли причин (пончик), распределение по классам, смерти по часам суток, переключатель периода 24 ч / 7 дней / всё время |
| **Книга Падших** | таблица с поиском, фильтрами (причина, класс, акт, только Hardcore), сортировкой по любому столбцу, пагинацией и карточкой смерти |

## Структура

```
index.html               разметка страницы
assets/css/style.css     вся визуальная система (темы, сетки, плеер, модалки)
assets/js/config.js      ← единственный файл для настройки API
assets/js/data.js        справочники PoE2 + агрегации (стартовый реестр пуст)
assets/js/store.js       аккаунты, сессии, запись смертей (localStorage / Supabase / API)
assets/js/charts.js      SVG-графики без библиотек
assets/js/tracks.js      реальные треки плейлиста (Spotify URI, названия, длительности)
assets/js/player.js      обёртка над Spotify iFrame API
assets/js/app.js         вся логика интерфейса
supabase/schema.sql      таблица deaths и правила RLS для общей статистики
server.py                необязательный бэкенд: HTTP + SQLite, без зависимостей
deploy.py                публикация статики на бесплатный хостинг (CodeSandbox)
deploy_github.py         публикация на GitHub Pages через REST API (без git)
```

## Запуск

```bash
python server.py            # http://127.0.0.1:8000  (статика + API)
```

Можно открыть и просто `index.html` — сайт работает автономно, но тогда
аккаунты и записи хранятся в localStorage браузера, а не на сервере.

### Общая статистика для всех посетителей (Supabase)

Статический GitHub Pages не умеет хранить данные, поэтому общий реестр живёт
в бесплатном проекте Supabase. Настройка занимает пару минут:

1. Зайдите на <https://supabase.com/dashboard> через GitHub и создайте проект
   (бесплатный тариф, регион ближе к аудитории).
2. Откройте **SQL Editor** → вставьте содержимое `supabase/schema.sql` → **Run**.
   Создадутся таблица `deaths` и правила RLS: читать и добавлять может каждый,
   изменять и удалять — никто.
3. **Project Settings → API**: скопируйте *Project URL* и ключ *anon public*.
4. Впишите их в `assets/js/config.js`:

```js
window.POE2_CONFIG = {
  supabase: {
    url: "https://xxxxxxxx.supabase.co",
    anonKey: "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
  }
};
```

После этого все посетители видят один и тот же реестр: страница подтягивает
новые записи каждые 30 секунд и при возврате на вкладку. Аккаунты остаются
локальными (пароли не уходят в облако), а записи, сделанные до подключения
облака, переносятся автоматически при входе.

`anon`-ключ публичный по дизайну Supabase — его защищают правила RLS, а не
секретность. Ограничения бесплатного тарифа (500 МБ, пауза после недели
простоя) для такого объёма данных избыточны.

### Включить настоящую регистрацию

1. Запустите `python server.py`.
2. В `assets/js/config.js` укажите адрес API:

```js
window.POE2_CONFIG = { apiBase: "http://127.0.0.1:8000/api" };
```

3. Обновите страницу: регистрация, вход и отчёты теперь идут через SQLite
   (`data/poe2track.db`), записи видны всем посетителям.

### API

| Метод | Маршрут | Назначение |
|---|---|---|
| POST | `/api/register` | `{email, password, name}` → `{user, session}` |
| POST | `/api/login` | `{email, password}` → `{user, session}` |
| POST | `/api/logout` | завершает сессию |
| GET | `/api/me` | профиль по `Authorization: Bearer <token>` |
| GET | `/api/deaths?limit=&offset=` | записи сообщества |
| POST | `/api/deaths` | новый отчёт (нужна авторизация) |
| GET | `/api/stats` | агрегаты по серверным данным |
| GET | `/api/health` | проверка живости |

## Spotify-плеер

Плеер использует официальный **Spotify iFrame Embed API** (`assets/js/player.js`):

* треки листаются кнопками ⏮ / ⏭ и кликом по списку (загрузка по `spotify:track:…`);
* громкость и mute — `setVolume()`;
* перемотка — `seek()`;
* play/pause — `togglePlay()`;
* по окончании трека автоматически включается следующий.

### Свои плейлисты

Кнопка **＋** рядом с выбором плейлиста (либо **＋ Плейлист** в строке громкости
на узких экранах) открывает окно «Свой плейлист». Достаточно вставить ссылку
Spotify — поддерживаются:

* плейлист, альбом, исполнитель, подкаст: `https://open.spotify.com/playlist/…`,
  `spotify:album:…` — играет целиком;
* отдельные треки: по одной ссылке в строке, можно подписать
  `Название — Исполнитель | https://open.spotify.com/track/…`.

Свои плейлисты хранятся в `localStorage` браузера (`poe2track.playlists.v1`),
поэтому у каждого посетителя они свои; в Supabase ничего не уходит. Активный
плейлист запоминается, а сохранённые можно переключать, не открывая окно, —
через выпадающий список в шапке списка треков.

Ограничение Embed API: у плейлиста/альбома нельзя получить список треков без
Spotify Web API и токена, поэтому внутри такого плейлиста треки листает сам
Spotify, а кнопки ⏮ / ⏭ и перемешивание отключаются. Собственный список
отдельных треков работает полностью: стрелки, перемотка, автопереход.

Нужен аккаунт Spotify; полные треки — только с Premium (ограничение самого Spotify,
не сайта). Если Spotify заблокирован (VPN, блокировщик), показывается ссылка на плейлист.

Чтобы поменять штатный плейлист, отредактируйте `assets/js/tracks.js`
(`playlistUrl`, `cover`, массив `tracks`). Список треков уже собран из реального
плейлиста «Path of Exile 2» — это тёмное фэнтези-амбиент-сопровождение.

## Публикация

Проект полностью статический (бэкенд необязателен), поэтому подходит любой
бесплатный статический хостинг.

**CodeSandbox (уже опубликовано, без регистрации):**

```bash
python deploy.py
```

Скрипт упаковывает `index.html` + `assets/` и печатает публичный адрес вида
`https://xxxxxx.csb.app`. При первом заходе CodeSandbox один раз спрашивает
«продолжить просмотр?» — это защита хостинга от фишинга; после подтверждения
открывается сайт. Чтобы убрать предупреждение совсем, сделайте fork песочницы
под своим аккаунтом CodeSandbox или используйте Netlify/GitHub Pages ниже.

**Netlify Drop:** перетащите папку проекта на <https://app.netlify.com/drop>.

**GitHub Pages (основной вариант, без git):**

```bash
python deploy_github.py --repo poe2-track
```

Скрипт работает через REST API GitHub — `git`, `gh` и Node.js не нужны. Он
проверяет токен, создаёт публичный репозиторий (если его нет), заливает
`index.html`, `assets/`, `README.md` и `.nojekyll` в ветку `main`, включает
Pages и печатает адрес `https://<user>.github.io/poe2-track/`. Повторный запуск
обновляет сайт.

Токен нужен classic со scope `repo` или `public_repo`:
<https://github.com/settings/tokens/new?scopes=repo&description=poe2-track>.
Передайте его скрытым вводом (`--token` не обязателен) или через переменную
окружения `GITHUB_TOKEN`. Проверить, что будет залито, можно так:
`python deploy_github.py --dry-run`.

Если git всё-таки установлен, классический путь тоже работает:

```bash
git init && git add . && git commit -m "PoE2 death tracker"
git remote add origin https://github.com/<user>/<repo>.git && git push -u origin main
# Settings → Pages → Deploy from branch → main / root
```

**Vercel / Cloudflare Pages:** framework preset — «Other», build command пустой,
output directory — корень репозитория.

## Данные

Сгенерированных записей нет. Реестр стартует пустым: единственный источник —
отчёты, добавленные через форму (в локальном режиме — localStorage, в серверном —
SQLite через `/api/deaths`). Пока записей нет, сводка и графики показывают
честные заглушки («данных пока нет»), а не выдуманную статистику.

Справочники в `data.js` — реальные данные игры: классы, вознесения, причины
смерти, локации по актам и боссы (Clearfell, Ogham Manor, Trial of the Sekhemas,
Utzaal, Xesht…). Они нужны для выпадающих списков формы и подписей на графиках.

Записи, добавленные игроками, помечаются как `community` и встают в начало реестра.

## Приватность и безопасность

* Пароли не хранятся в открытом виде: PBKDF2-SHA256, 120 000 итераций, соль 128 бит.
* В локальном режиме данные не покидают браузер. В серверном — SQLite на вашем хосте.
* Для публичного продакшена добавьте HTTPS, ограничение частоты запросов и
  подтверждение e-mail — в этой версии их нет.
